# AI掘金头条新闻系统 (Toutiao News)

一个基于 FastAPI 和 SQLAlchemy 构建的现代化新闻系统，支持用户注册登录、新闻浏览、收藏、历史记录和 AI 问答等功能。

## 1-1 项目概述

这是一个仿今日头条的新闻系统后端 API 服务，采用异步 Python 框架 FastAPI 开发，使用 MySQL 作为数据库存储，通过 SQLAlchemy ORM（异步）进行数据访问，Redis 作为缓存层，并集成 DeepSeek 大模型提供 SSE 流式 AI 对话能力。系统提供完整的用户管理、新闻浏览、收藏、历史记录和 AI 问答功能。

## 1-2 技术栈

- **后端框架**: FastAPI + Pydantic v2
- **数据库**: MySQL 8
- **ORM**: SQLAlchemy 2.0（异步 `async`）
- **数据库驱动**: aiomysql
- **密码加密**: passlib + bcrypt
- **缓存系统**: Redis（`redis.asyncio`）
- **AI 调用**: httpx（流式转发 OpenAI 兼容接口）
- **依赖管理**: uv（`pyproject.toml` + `uv.lock`）
- **配置管理**: .env 环境变量（DB / Redis / AI 凭据）

## 1-4 功能模块

### 1. 用户管理模块

- 用户注册（用户名唯一校验、bcrypt 密码哈希）
- 用户登录（校验密码、生成/更新 token）
- 用户信息获取 / 更新（局部更新 `exclude_unset`，手机号唯一性校验）
- 用户密码修改

### 2. 新闻模块

- 新闻分类获取（Redis 缓存）
- 新闻列表获取（分页 + 分类筛选，Redis 缓存）
- 新闻详情获取（浏览量 +1，Redis 缓存）
- 相关新闻推荐（同分类按浏览量/时间排序，Redis 缓存）

### 3. 收藏模块

- 检查收藏状态 / 添加收藏（唯一约束防重复）/ 取消收藏
- 收藏列表获取（分页）/ 清空所有收藏

### 4. 浏览历史模块

- 添加浏览记录（同一用户同一新闻只保留一条，更新浏览时间）
- 浏览历史列表获取（分页）/ 删除单条 / 清空

### 5. AI 对话模块

- `POST /api/chat/stream`：登录鉴权后，httpx 流式转发 DeepSeek，`StreamingResponse` 原样透传 SSE 分片
- system prompt 由后端统一注入（过滤前端传入的 system 消息，防篡改）
- 密钥仅存后端 `.env`，前端不接触

### 6. 缓存模块

- 新闻分类缓存 / 新闻列表缓存 / 新闻详情缓存 / 相关新闻缓存
- 采用 Cache-Aside（旁路缓存）模式，缓存故障静默降级

## 1-5 数据库设计

共 8 张业务表（由 `database.sql` 定义）：

| 表名 | 说明 | 关键字段 |
| --- | --- | --- |
| `user` | 用户信息 | username（唯一）、password（bcrypt 哈希）、avatar、phone（唯一） |
| `user_token` | 认证令牌 | user_id（外键）、token（唯一）、expires_at（7 天过期） |
| `news_category` | 新闻分类 | name（唯一）、sort_order |
| `news` | 新闻 | title、content、category_id（外键）、views、publish_time |
| `related_news` | 相关新闻关联 | news_id、related_news_id（唯一约束） |
| `favorite` | 收藏记录 | user_id + news_id（联合唯一约束，防重复收藏） |
| `history` | 浏览历史 | user_id + news_id、view_time（联合索引优化查询） |
| `ai_chat` | AI 聊天记录 | user_id、message、response（预留，暂未实现持久化） |

外键均带 `ON DELETE CASCADE`，删除用户/新闻自动清理关联数据；高频查询字段建有索引（`username_UNIQUE`、`fk_news_category_idx`、`idx_publish_time`、`idx_user_viewtime` 等）。

## 1-6 缓存设计

### 缓存策略

系统采用 **Cache-Aside（旁路缓存）读模式**：读未命中 → 回源数据库 → 回填缓存；配合 TTL 过期淘汰与故障静默降级（Redis 不可用时打印错误返回 None，不影响接口主流程）。

### 缓存键与过期时间

| 缓存项 | 缓存键 | 过期时间 |
| --- | --- | --- |
| 新闻分类 | `news:categories` | 2 小时（7200s） |
| 新闻列表 | `news:list:{category_id}:{page}:{size}` | 10 分钟（600s） |
| 新闻详情 | `news:detail:{news_id}` | 30 分钟（1800s） |
| 相关新闻 | `news:related:{news_id}:{category_id}:{limit}` | 10 分钟（600s） |

### 缓存实现要点

- 写缓存统一用 `model_dump(mode="json", by_alias=False)` 转成 JSON 安全的 dict（datetime 转 ISO 字符串），避免序列化失败
- 读写 key 必须完全对称（如相关新闻的 `limit` 参与 key 组成，读写都要传）
- 命中/未命中两个分支返回结构保持一致，避免接口响应格式分裂

### 缓存配置

Redis 连接信息在 `.env` 中配置，`config/cache_conf.py` 启动时读取：

```dotenv
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=你的Redis密码
REDIS_DB=0
```

### 已知局限与改进计划

当前实现为 Cache-Aside 读路径 + 过期淘汰，存在以下可迭代改进点：

- **写路径缓存滞后**：浏览量 `increase_news_views` 直更 DB，详情缓存中的 `views` 需等过期后才回源（业务可接受）。改进：更新 DB 后删除缓存键（Cache-Aside 标准写路径），或 Redis `INCR` 异步合并写库。
- **缓存穿透 / 击穿 / 雪崩**：未做防护。改进：空值缓存或布隆过滤器（穿透）、逻辑过期 + 互斥锁（击穿）、TTL 随机抖动（雪崩）。
- **冷启动预热**：服务重启后首次访问逐条回源。改进：启动时预加载热点数据。

## 1-8 认证机制

系统使用自建 Token 表（非 JWT）认证：

1. 注册/登录成功后生成 UUID token，存入 `user_token` 表，有效期 **7 天**（登录会刷新旧 token）
2. 需认证接口在请求头添加 `Authorization: Bearer <token>`（注意 `Bearer` 前缀 + 空格）
3. 后端 `get_current_user` 依赖：解析 token → 查 `user_token` 表 → 校验过期 → 返回用户
4. token 存服务端数据库，可主动撤销（删除记录即可强制下线）
5. 密码使用 bcrypt 加盐哈希存储（成本因子 12），绝不存明文

## 1-9 错误处理

系统提供统一的错误处理机制（全局异常处理器 + 统一响应封装）：

- 用户认证失败 / token 无效：401
- 请求参数校验失败：422（FastAPI 自动）
- 资源不存在：404
- 服务器内部错误：500
- 业务错误：HTTPException 携带 detail，统一返回 `{code, message, data}` 结构

## 1-10 开发规范

- 使用异步数据库操作（async/await，禁止在异步中做阻塞 IO）
- 所有密码均加密存储（bcrypt），密钥仅存 `.env`
- 接口返回统一的 JSON 格式（`{code, message, data}`）
- 分层职责清晰：routers 不写 SQL、crud 不关心 HTTP
- 缓存操作封装成独立函数（cache/ 目录），读写 key 对称、分支返回类型一致
- 配置统一走 `.env`（`config/env_loader.py` 加载），不硬编码任何凭据
- 踩坑经验沉淀到《踩坑记录.md》（37 条），新坑必须追加记录

## 1-11 性能优化

- Redis 缓存热点数据（分类/列表/详情/相关新闻，Cache-Aside 模式）
- 异步数据库操作提升并发性能（同资源支撑更多并发连接）
- 合理的数据库索引设计（高频查询字段、联合索引）
- 连接池管理减少连接开销（`pool_size=10, max_overflow=20`）
- 列表接口分页查询（`OFFSET/LIMIT`），避免全量加载
